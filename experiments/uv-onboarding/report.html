Experiment report · 17 Aug 2026

Pouch Onboarding Pipeline

Can an arbitrary existing 3D product model become a customization-ready asset — 2D template in, correct 3D preview out? Tested end-to-end on the Meshy AI stand-up pouch.

Result: success. The raw Meshy GLB was converted into product-customizable.glb + regions.json + uv-template.svg, and a real three.js harness (same CanvasTexture → TEXCOORD_0 path as the production configurator) placed artwork at four 2D canvas positions — each appeared exactly where predicted on the 3D pouch.
Licensing blocker found: PartField — and PartUV as shipped, which vendors it — is under the NVIDIA license, restricted to non-commercial research use, and the restriction propagates to derivative works. The PartField→PartUV route is legally unusable for this commercial product regardless of technical merit. The approved unwrap library is pip xatlas (MIT).

The proof

What the raw Meshy mesh looks like

440k triangles, 1,764 disconnected components — three real shells (front, back, gusset) plus ~1,700 floating debris shells (0.9% of surface area) that put visible specks on any artwork. One UV atlas with 1,758 charts, but semantically better than expected: front and back panels are each a single large chart. Orientation is mirrored and island edges wobble with the wrinkles — class C: usable only after semantic labeling and rearrangement.

Key insight: mathematical UV quality and customer usability are anti-correlated on this object class. xatlas wins every metric and is the least usable; a customer needs predictable fixed rectangles. Deliberate distortion at wrinkles is correct — flat artwork drapes over creases the way printed film actually does.

Recommended architecture

INPUT GLB
  → Inspect (trimesh: components, charts, checker render)   [automated]
  → Clean (drop debris components)                          [automated]
  → Existing-UV triage: keep & relayout, or continue        [automated + human glance]
  → Semantic region assignment                              [the human step, 10–30 min]
  → CUSTOMIZATION_UV: per-region projection into FIXED
    reserved rectangles (predictability > packing)          [automated]
  → Export GLB (TEXCOORD_0 = customization,
    TEXCOORD_1 = original UV + texture, named meshes)
    + regions.json + uv-template.svg + diagnostics          [automated]
  → three.js validation harness                             [automated]
  → register in product-config.ts → existing configurator

No GPU, no ML, no non-commercial code. The 3D model contributes geometry; the 2D template is authored as fixed rectangles and projected onto it — the same philosophy as Pacdora/Zakeke, arrived at by measurement. The next engineering investment is the human step: a click-region-→-name-it labeling tool emitting regions.json, not a segmentation model.

What still can't be automated

  • Semantic region detection for arbitrary shapes — pouch heuristics don't transfer to shoes; no commercially-licensed automatic part segmentation exists off-the-shelf.
  • Projection choice per product family (planar / cylindrical / conformal).
  • Physical scale — AI meshes are unitless; real mm must come from the client.
  • glTF drops UV-set names — order is the contract (0 = customization, 1 = original), recorded in regions.json.
  • Meshy regeneration instability — every regenerated mesh re-runs onboarding.
